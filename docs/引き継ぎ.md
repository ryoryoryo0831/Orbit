## ビルドと公開の流れ

ローカルには Android SDK・Xcode・Mac が無いので、**ビルドはすべて GitHub Actions** で行う。

1. 作業用ブランチ **`main-t49pwm`** で変更して push する。
   - `android/**` を変えると Android のビルド（`.github/workflows/android.yml`）が走る。
   - `ios/**` を変えると iPhone のビルド（`.github/workflows/ios.yml`、Mac の環境）が走る。
   - 作業用ブランチでは**ビルドとテストだけ**行い、公開はしない。
2. ビルドが通ったらユーザーに報告し、許可をもらってから **main に早送り（fast-forward）で反映**する。
   - `git push origin main-t49pwm:main`
3. main に入ると自動で Releases に公開される。
   - **Android**：タグ `build-N`、名前「Orbit 1.0.N」、**最新版（latest）にする**。
   - **iPhone**：タグ `ios-build-N`、名前「Orbit iOS 1.0.N」、**最新版にはしない**（Android の最新版ページを変えないため）。
4. バージョンの末尾 N は、それぞれのワークフローの実行番号。作業用ブランチのビルドでも番号が進むので、公開版の番号は飛ぶ（例：1.0.28 の次が 1.0.34）。ユーザーに版の番号を伝えるのは、公開が終わって番号が分かってから。
5. `docs/` だけの変更ではビルドは走らない。メモの更新は作業用ブランチに入れておき、次の公開のときに一緒に main へ入る。

### ビルドの状況の確かめ方

- `gh` は使えない。GitHub MCP のツールか、公開 API（`curl https://api.github.com/repos/ryoryoryo0831/video-player/actions/runs/<id>`）で確認する。
- 待つときは、裏で動かすコマンドで完了を待つ（`sleep` で待たない）。例：`/actions/runs?head_sha=<コミット>` を 30 秒ごとに見て、`completed` になったら終わる。
- 公開が済んだかは `curl https://api.github.com/repos/ryoryoryo0831/video-player/releases/latest` で版の名前と APK のファイル名を確かめる。
- ローカルではビルドできないので、大きな変更のあとは別のエージェントに差分を読ませて、コンパイルエラーと不具合を探してもらうと安全（2026-10-10 はこれで 3 つの不具合を公開前に直せた）。

### 署名

- Android は GitHub の Secrets（`KEYSTORE_BASE64` / `KEYSTORE_PASSWORD`）の鍵で署名する。main で鍵が無いと公開を中止する。
- 鍵の元ファイル（`release.p12`）はユーザーの PC の `signing/` フォルダと Google ドライブにある。リポジトリには入れない。
- iPhone 版は署名しない .ipa を作り、SideStore が入れるときに署名する（無料の Apple ID・7日ごとに更新）。

## 気をつけること（これまでの失敗から）

- **自由な小窓は「他のアプリの上に重ねて表示」の許可が無いと出ない。** 許可が無いと OS の小窓になり、ユーザーには「端に寄せられない・小さくならない」と見える（1.0.26 で起きた）。小窓の不具合の報告では、まずどちらの小窓が出ているか（左上に ✕・右上に全画面・右下に斜めの矢印があれば自由な小窓）を確かめる。
- Android の OS の小窓は、ボタンの数・最小の大きさ・置ける場所を OS が決めるので、アプリからは変えられない。
- 返答を英語で書いてしまったことがあり、ユーザーから「絶対に日本語で」と言われた。
- **推測で直して「原因がわかりました」と言ってしまった**（1.0.44 の自由な小窓）。ユーザーから強く指摘された。不具合は、まず関係するコード（ライブラリも含む）を読んで原因を確かめてから直す。libVLC のソースは Maven Central の `libvlc-all-<版>-sources.jar` から取れる（`repo1.maven.org` は見える。一度目は回数制限で失敗することがある）。報告では「確かめたこと」と「推測」を分けて書く。
- 1.0.51 で全画面に戻しても映るようになった（ユーザーの実機で確認。どちらの向きも約 2 秒かかる）。2 秒は、映像を途中から出し直すと VLC が次のキーフレームまで映像を捨てるため（`packetizer/h264.c`）。`restoreVideo` で再生中でも同じ位置へ移動し直し、全画面の見張りの待ちも 0.25 秒にした（1.0.53）。
- 1.0.49 で小窓は数秒待つと映るようになった（ユーザーの実機で確認）。ただし小窓から全画面に戻ると映像が出なかった。再生画面を新しく作るので、同じ「出し先の準備前に映像を頼む」問題が起きていた。再生画面でも `IVLCVout.Callback` で出し先の準備を見張り、1 秒たっても Vout イベントが来なければ映像を出し直す（1.0.51）。
- 自由な小窓に映像が出なかった原因その2（1.0.46 でも映らなかった）：新しい窓の SurfaceView はすぐには準備できないのに、小窓を出すと同時に映像トラックを有効にしていた。VLC の native 側（`modules/video_output/android/display.c`）は出し先が無いと "can't get Video Surface" で失敗し、待たない・やり直さない。MediaPlayer もトラックが選ばれたままだと出し直さない。`IVLCVout.Callback.onSurfacesCreated` で映像を止めて出し直すように直した（作業用ブランチ・未公開）。映像が 4 秒たっても出ないときは、小窓に止まった場所を小さく表示する。
- 自由な小窓に映像が出なかった原因その1：libVLC の `VideoHelper.updateVideoSurfaces` は、`VLCVideoLayout` が Activity の中にあるときしか `setWindowSize` を呼ばない。サービスから出す窓では、`vlcVout` に SurfaceView を直接つないで、`setWindowSize` を自分で呼ぶ必要がある。
