## ビルドと公開の流れ

ローカルには Android SDK・Xcode・Mac が無いので、**ビルドはすべて GitHub Actions** で行う。

1. 作業用ブランチ **`main-t49pwm`** で変更して push する。
   - `android/**` を変えると Android のビルド（`.github/workflows/android.yml`）が走る。
   - `ios/**` を変えると iPhone のビルド（`.github/workflows/ios.yml`、Mac の環境）が走る。
   - 作業用ブランチでは**ビルドとテストだけ**行い、公開はしない。
2. ビルドが通ったら、許可を待たずに **main に早送り（fast-forward）で反映**する（2026-10-18 から）。公開した版の番号をユーザーに伝える。
   - `git push origin main-t49pwm:main`
3. main に入ると自動で Releases に公開される。
   - **Android**：タグ `build-N`、名前「Orbit 1.0.N」、**最新版（latest）にする**。
   - **iPhone**：タグ `ios-build-N`、名前「Orbit iOS 1.0.N」、**最新版にはしない**（Android の最新版ページを変えないため）。
4. バージョンの末尾 N は、それぞれのワークフローの実行番号。作業用ブランチのビルドでも番号が進むので、公開版の番号は飛ぶ（例：1.0.28 の次が 1.0.34）。ユーザーに版の番号を伝えるのは、公開が終わって番号が分かってから。
5. `docs/` だけの変更ではビルドは走らない。メモの更新は作業用ブランチに入れておき、次の公開のときに一緒に main へ入る。

### ビルドの状況の確かめ方

- ユーザーの PC では `gh` が使える。`gh run list --branch <ブランチ> --commit <sha>` で実行を探し、`gh run watch <id> --exit-status` で待ち、`gh run view <id> --log` で `BUILD SUCCESSFUL`・Lint の件数・`e: ...kt:行:列`（コンパイルエラー）を見る。公開が済んだかは `gh release view` で版の名前と APK のファイル名を確かめる。
- （クラウドのセッションでは `gh` が無いので、公開 API `https://api.github.com/repos/ryoryoryo0831/video-player/actions/runs?head_sha=<コミット>` を使う。）
- ローカルではビルドできないので、大きな変更のあとは別のエージェントに差分を読ませて、コンパイルエラーと不具合を探してもらうと安全（2026-10-10 はこれで 3 つの不具合を公開前に直せた）。

### 署名

- Android は GitHub の Secrets（`KEYSTORE_BASE64` / `KEYSTORE_PASSWORD`）の鍵で署名する。main で鍵が無いと公開を中止する。
- 鍵の元ファイル（`release.p12`）はユーザーの PC の `signing/` フォルダと Google ドライブにある。リポジトリには入れない。
- iPhone 版は署名しない .ipa を作り、SideStore が入れるときに署名する（無料の Apple ID・7日ごとに更新）。

コード全体を見直して見つけた問題を、まとめて直した。

**① 再生画面の色と下の帯（1.0.55 で公開・実機未確認、2026-10-11 ローカルのセッション）**：ライブラリのソースで原因を確かめてから直した。
- 紫っぽい色：再生画面のテーマ（`Theme.VideoPlayer.Player`）が 4 色しか決めておらず、残りが Material 3 の初期値（紫）だった。シークバーは `colorControlActivated` →（初期値）`colorAccent` → `colorSecondary`、︙メニューの背景は `colorSurfaceContainerLow` を使う。暗いテーマの色を `values/colors.xml` の `dark_*` にまとめ（`values-night` はそれを参照）、再生画面のテーマで全部の色を決めた。シークバーは両方のテーマでアクセントの青にした（音楽画面のシークバーも灰色だった）。
- 下の帯：`SystemBarStyle.auto` だと activity 1.12 の `enableEdgeToEdge` が `isNavigationBarContrastEnforced = true` にするので、3 ボタンのナビゲーションに OS が半透明の幕を重ねていた。`SystemBars.kt` の `enableEdgeToEdgeWithoutScrim()`（明るい・暗いをはっきり指定）に置き換えた。︙メニュー（`ActionSheet`）も窓の幕を消し、ナビゲーションバーを透明にしてシートの背景を下まで見せる（`clearNavigationBarScrim`）。

  - 「動画をやめて別のアプリを使い、時間がたってからアプリの一覧から戻ると最初から再生される・設定が戻る」：**確かめた原因**は 2 つ。① 再生サービスが終わっていたとき、動画の画面は最初に開いたときの Intent で開き直していた（次の話に進んでいても最初の話を最初から）。今は `LastSession`（前回の続き）を先に使い、無いときだけ Intent（`PlayerActivity.onServiceReady` の fallback）。② DVD（ISO）は「メニューから始める」設定だと続きの位置を使わず、時間しか覚えていなかった。`ResumeStore.saveTitle/getTitle`（どのタイトル＝話か）を覚え、`restoreLastSession` のとき（`resumeDiscOnce`→`resumeDiscGen`）はメニューを出さずにそのタイトルの続きから（`DiscController.prepare(..., resumeTitle)`）。メニューの中の位置は覚えない。手で選んだ音声・字幕は `TrackChoiceStore`（SharedPreferences）に覚える（以前はアプリを閉じるまで）。

## 見送ったこと（理由つき）

- **Android の APK の縮小（R8）**：実機で確かめないと動かなくなる危険があるため。
- **大きなファイルの分割、Media3 への移行**：作り直しに近い規模で、見た目の改善がないため。
- **多言語対応**：日本語だけで使うため。
