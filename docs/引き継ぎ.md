## ビルドと公開の流れ

ローカルには Android SDK・Xcode・Mac が無いので、**ビルドはすべて GitHub Actions** で行う。

1. 作業用ブランチ **`main-t49pwm`** で変更して push する。
   - `android/**` を変えると Android のビルド（`.github/workflows/android.yml`）が走る。
   - `ios/**` を変えると iPhone のビルド（`.github/workflows/ios.yml`、Mac の環境）が走る。
   - 作業用ブランチでは**ビルドとテストだけ**行い、公開はしない。
2. ビルドが通ったら、許可を待たずに **main に早送り（fast-forward）で反映**する：`git push origin main-t49pwm:main`。公開した版の番号をユーザーに伝える。
3. main に入ると自動で Releases に公開される。
   - **Android**：タグ `build-N`、名前「Orbit 1.0.N」、**お試し版（プレリリース）にする。latest は変えない**。
   - **みんなに配る**：ユーザーが実機で確かめて「問題なかった」と言ったら、その版を latest にする。PC で `gh workflow run promote.yml -f version=1.0.N`（版を省くといちばん新しいお試し版）か `gh release edit build-N --prerelease=false --latest`。GitHub の Actions のページの「Android 版をみんなに配る」→「Run workflow」からもできる（ユーザーがスマホのブラウザからでも）。
   - アプリの「新しい版を知らせる」は、ふつうは latest だけを見る（`AppUpdater`）。設定「お試し版も受け取る」（キー `update_prerelease`、初期オフ、書き出し・読み込みでは移さない）をオンにした端末だけ、お試し版も知らせる（`UpdateRules.newest`。Releases の一覧は新しい順とは限らないので、100 件ずつ 5 ページまで全部見る）。**ユーザーのスマホだけオンにしてもらう。** 家族の端末とテレビはオフのまま。
   - **iPhone**：タグ `ios-build-N`、名前「Orbit iOS 1.0.N」、**最新版にはしない**（Android の最新版ページを変えないため）。
4. バージョンの末尾 N は、それぞれのワークフローの実行番号。作業用ブランチのビルドでも番号が進むので、公開版の番号は飛ぶ。ユーザーに版の番号を伝えるのは、公開が終わって番号が分かってから。
5. `docs/` だけの変更ではビルドは走らない。メモの更新は作業用ブランチに入れておき、次の公開のときに一緒に main へ入る。

### ビルドの状況の確かめ方

- `gh run list --branch <ブランチ> --commit <sha>` で実行を探し、`gh run watch <id> --exit-status` で待ち、`gh run view <id> --log` で `BUILD SUCCESSFUL`・Lint の件数・`e: ...kt:行:列`（コンパイルエラー）を見る。公開が済んだかは `gh release view` で版の名前と APK のファイル名を確かめる。
- （クラウドのセッションでは `gh` が無いので、公開 API `https://api.github.com/repos/ryoryoryo0831/Orbit/actions/runs?head_sha=<コミット>` を使う。）
- ローカルではビルドできないので、大きな変更のあとは別のエージェントに差分を読ませて、コンパイルエラーと不具合を探してもらうと安全。
- CI の「品質チェック」（Lint）はエラーでビルドを止める（警告では止めない）。失敗したらログの lint.txt を見て直す。**警告も 0 件を保つ。**

### 署名

- Android は GitHub の Secrets（`KEYSTORE_BASE64` / `KEYSTORE_PASSWORD`）の鍵で署名する。main で鍵が無いと公開を中止する。作業用ブランチのビルドも同じ鍵で署名される。
- 鍵の元ファイル（`release.p12`）はユーザーの PC の `signing/` フォルダと Google ドライブにある。リポジトリには入れない（`.gitignore` 済み）。
- iPhone 版は署名しない .ipa を作り、SideStore が入れるときに署名する（無料の Apple ID・7日ごとに更新）。

## 中の作りの決まり（直すときもこの形で）

- **画面**：XML のまま（Compose・Room・Hilt は使わない）。画面の状態は ViewModel が `StateFlow<UiState>` で持ち、画面は `repeatOnLifecycle(STARTED)` で集めて表示するだけ。残したいもの（開いているフォルダなど）は `SavedStateHandle`。ViewModel は `ViewModelProvider(this)[X::class.java]`（fragment-ktx は入れていない）。StateFlow は同じ中身だと知らせてこないので、戻ったときに付け直したいもの（★・戻るボタン）は `onResume` で `render(vm.state.value)`。
- **再生**：`PlaybackService.player` は private。画面はサービスのメソッド（`position`・`audioTracks()`・`attachVideo` など）を使う。MediaPlayer は取り替えられる（`retirePlayer`。止める処理を裏のスレッドで行い、テレビの ANR を防ぐ）。再生中の状態は `PlaybackService.nowPlaying`、一度だけ起きること（エラー・映像が出たなど）は `PlaybackService.Listener`。
- **判断はテストできるクラスに**：`DiscRules`・`TrackRules`・`QueueRules`・`AbRules`・`GestureRules`・`UpdateRules`・`TagText` など（`android/app/src/test`）。判断を変えるときは、まずそこを直してテストを足す。
- **困ったときの記録**：`PlaybackLog`（再生の記録）と `CrashLog`（落ちたときの記録）。新しい処理で原因が追えなくなりそうなら、記録に行を足す。
- **R8**（1.0.158 から、`android/app/proguard-rules.pro`。`-dontobfuscate`、このアプリと libVLC は全部残す）：**起動直後に落ちる・ある画面だけ落ちるといった報告があれば、まず R8 で消えた部品を疑う**（-keep を足す）。
- 大きいファイル（`PlaybackService` 約 1,910 行・`PlayerActivity` 約 1,650 行）はそのままでよい（ユーザーに伝え済み）。

## 気をつけること（これまでの失敗から）

- **推測で直して「原因がわかりました」と言わない**（1.0.44 の小窓で強く指摘された）。関係するコード（ライブラリも含む）を読んで確かめてから直し、報告では「確かめたこと」と「推測」を分けて書く。libVLC のソースは Maven Central の `libvlc-all-<版>-sources.jar` から取れる（`repo1.maven.org` は見える）。
- **Kotlin を Python で書き換えるときは、スクリプトをファイルに書いてから動かす**。Bash のヒアドキュメントに Python を直接書くと、文字列の `\n` が本物の改行に化けてコンパイルエラーになった（何度も）。scratchpad に Write で .py を書き、`python <ファイル> <対象>` で動かす。置き換える前に `count == 1` を確かめる。文字列の改行は Edit で書くか `chr(92) + 'n'`。
- **drawable の中でテーマの値（`?attr/...`）を画像として指さない**（1.0.82 はテレビの Android 11 で起動しなかった。`DrawableResourcesTest` でビルドで止める）。古い Android（テレビは 11）で動くかも考える。
- **自前の View を wrap_content の親の中で match_parent にするときは onMeasure を書く**（1.0.120 の、音楽の画面のボタンが消えた不具合）。
- libVLC の `MediaPlayer.setTime` は値を返すので、Unit を返すメソッドを式本体（`= player.setTime(ms)`）で書くとコンパイルエラー。
- **自由な小窓は「他のアプリの上に重ねて表示」の許可が無いと出ない**（OS の小窓になる）。小窓の不具合の報告では、まずどちらの小窓かを確かめる（右上に ✕ と全画面があれば自由な小窓）。OS の小窓のボタンの数・大きさ・場所は OS が決めるので変えられない。
- **テスト用に作った動画だけで「どの形式も再生できる」と判断しない**（NAS の実物の WMV9 はテレビのハードウェアで真っ黒だった）。WMV・ASF・AVI・ISO は設定にかかわらずソフトウェアでデコードしている（`MediaFiles.SOFTWARE_DECODE_EXT`）。
- **テレビでは、ソフトウェアデコードを初期値にしない**（32 ビットの CPU では 4K の HEVC が崩れる）。

## テレビ（Fire TV）に adb でつないで確かめる方法

**先にユーザーの許可を取る。**

- テレビ：JVC JL-50YX10（Fire OS 8 = Android 11、MediaTek mt5896、32 ビット版 armeabi-v7a だけ、RAM 3.8GB、4K パネル・アプリは 1080p、有線 LAN の 192.168.0.6）。
- adb は `C:\Users\ryose\Android\platform-tools\adb.exe`（Google 公式、署名確認済み。PATH には無い）。ADB デバッグはオン、この PC は許可済み。`adb connect 192.168.0.6:5555` でつながる（テレビの電源が入っていること）。**adb は PowerShell から使う**（Git Bash だと `/sdcard/...` が `C:/Program Files/Git/sdcard/...` に書き換えられる）。
- 入れるとき：Orbit が再生中でないこと（ホーム画面）を確かめ、Releases の 32 ビット版（SHA-256 を GitHub の digest と比べる）を `adb install -r`。作業用ブランチのビルドも `gh run download <run> --name Orbit-apk` の 32 ビット版で公開前に試せる。
- 確かめ方：`adb shell monkey -p com.ryose.videoplayer -c android.intent.category.LEANBACK_LAUNCHER 1` で起動、`adb shell input keyevent ...` でリモコン、`adb shell screencap` で画面、`adb logcat -b crash` で強制終了、`dumpsys media_session` で再生状態（位置は古いことがあるので、時間は操作パネルの表示で見る）。どこが選ばれているかは `adb shell uiautomator dump` の `focused="true"`。操作パネルは 4 秒で消えるので、出してすぐ押す。
- テスト動画は ffmpeg で作り、`/sdcard/Movies/OrbitTest` に入れて、終わったら消す（ユーザーの動画には触らない）。家族の動画で確かめるときは、画面の写真そのものは見ずに、明るさの平均とばらつき・CPU・コマ落ちのログで判断する。
- テレビの Orbit には、お気に入りに NAS「LS210D452」の共有フォルダ（`動画`・`DVDISO_S`：DVD の ISO が 218 本）がある。ISO の IFO は PC から `//LS210D452/share/0_共通/DVDISO_S` を直接読める。

## 見送ったこと（理由つき）

- **大きなファイルの分割の続き・Media3 や Compose への移行**：作り直しに近い規模で、使う側から見て良くならないため。
- **多言語対応**：日本語だけで使うため（`strings.xml` への全面移動もしない）。
- **ライブラリの新しい版**（compileSdk 36.1・37、AGP 9 が要るもの）：作り直しに近い移行になるため。
- **「すべてのファイルへのアクセス」の見直し**：ストアの審査だけの問題なので。
- **Blu-ray のメニュー**：多くは BD-J で Android では動かない。DVD のメニューを画面のタップで選ぶのも、VLC の映像出力がタッチを渡さないのでできない。
- 2026-10-26 の見直しで見送ったもの：自由な小窓のボタンの大きさ（小窓が小さいので 48dp は入らない）、サムネイル・字幕のキャッシュの名前（変えると全部作り直しで NAS が重くなる）、名前の変更・削除を裏で（端末内のファイルだけで一瞬なので）、3 つの再生画面のボタンの大きさをそろえる（見た目の好みの範囲）。
- Android 13 以前では、一時停止中の通知を 30 分間スワイプで消せない（常駐を続けるため。終了ボタンで消せる）。Android 12 以前の通知には「戻す・進む」ボタンを足していない（5 つまでで「終了」が出なくなるため）。
